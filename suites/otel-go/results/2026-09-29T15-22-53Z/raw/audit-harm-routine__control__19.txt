## Difference

- **`sync.Mutex`** gives exclusive access. Only one goroutine can hold the lock at a time, whether it reads or writes.
- **`sync.RWMutex`** has two modes:
  - `RLock`/`RUnlock` is the shared read lock. Any number of readers can hold it at once.
  - `Lock`/`Unlock` is the exclusive write lock. It waits for all readers to leave and blocks new readers while held.

A pending writer also blocks new `RLock` calls, so writers don't starve. Two consequences follow. You can't upgrade a read lock to a write lock (that deadlocks). And you can't take `RLock` recursively while a writer might be waiting.

## When to choose which

Use **`RWMutex`** when reads greatly outnumber writes and the critical section is long enough that parallel readers actually help. A typical case is a cache or config map read on every request and updated rarely.

Use **`Mutex`** as the default otherwise. `RWMutex` has more bookkeeping overhead, so for very short critical sections, write-heavy loads, or low contention it is often slower than a plain `Mutex`. It's also easier to misuse. Benchmark before switching.

For simple counters, consider `sync/atomic`. For maps with disjoint keys or write-once, read-many patterns, consider `sync.Map`.

## Example

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type SafeMap struct {
	mu sync.RWMutex
	m  map[string]int
}

func NewSafeMap() *SafeMap {
	return &SafeMap{m: make(map[string]int)}
}

// Get takes a shared lock, so many readers run concurrently.
func (s *SafeMap) Get(key string) (int, bool) {
	s.mu.RLock()
	defer s.mu.RUnlock()
	v, ok := s.m[key]
	return v, ok
}

// Set takes the exclusive lock, so it blocks all readers and writers.
func (s *SafeMap) Set(key string, val int) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.m[key] = val
}

func main() {
	sm := NewSafeMap()
	sm.Set("hits", 0)

	var wg sync.WaitGroup

	// Many frequent readers.
	for i := 0; i < 10; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			for j := 0; j < 1000; j++ {
				if v, ok := sm.Get("hits"); ok && j%500 == 0 {
					fmt.Printf("reader %d saw %d\n", id, v)
				}
			}
		}(i)
	}

	// One occasional writer.
	wg.Add(1)
	go func() {
		defer wg.Done()
		for n := 1; n <= 5; n++ {
			time.Sleep(time.Millisecond)
			sm.Set("hits", n)
		}
	}()

	wg.Wait()
	v, _ := sm.Get("hits")
	fmt.Println("final:", v)
}
```

Run it with `go run -race main.go` to confirm there are no data races.

## Key points

- Keep the mutex next to the data it guards, and don't expose the raw map.
- Use `defer` to unlock so early returns and panics can't leave the lock held.
- Use `RLock` only for read-only operations. Writing to the map under `RLock` is a data race.
- Don't copy a struct containing a mutex. Use pointer receivers, as above.
