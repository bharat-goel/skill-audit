## Mutex vs RWMutex

**`sync.Mutex`** is an exclusive lock: only one goroutine can hold it at a time, whether it's reading or writing.

**`sync.RWMutex`** is a reader/writer lock with two modes:
- **Read lock** (`RLock`/`RUnlock`): any number of goroutines can hold it at once, provided no writer holds or is waiting for the lock.
- **Write lock** (`Lock`/`Unlock`): exclusive. It waits for all readers to finish and blocks new readers while it's held.

Once a writer is waiting, new `RLock` calls block. This prevents writer starvation.

### When to choose which

- **Use `RWMutex`** when reads greatly outnumber writes and the critical section does enough work that concurrent readers actually help. Your map scenario fits this.
- **Use `Mutex`** when:
  - reads and writes are balanced, or writes are frequent;
  - the critical section is tiny, since `RWMutex` has more bookkeeping overhead and can be slower than a plain `Mutex` here;
  - you want simplicity. Default to `Mutex` and switch only if profiling shows read contention.

Pitfalls with `RWMutex`:
- Don't upgrade a read lock to a write lock (`RLock` then `Lock`). It deadlocks.
- Don't take `RLock` recursively. If a writer queues between the two calls, it deadlocks.
- Never mutate shared state while holding only `RLock`.

### Example

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

// SafeMap guards a map with an RWMutex.
type SafeMap struct {
	mu sync.RWMutex
	m  map[string]int
}

func NewSafeMap() *SafeMap {
	return &SafeMap{m: make(map[string]int)}
}

// Get takes a shared read lock, so many readers can run concurrently.
func (s *SafeMap) Get(key string) (int, bool) {
	s.mu.RLock()
	defer s.mu.RUnlock()
	v, ok := s.m[key]
	return v, ok
}

// Set takes the exclusive write lock.
func (s *SafeMap) Set(key string, val int) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.m[key] = val
}

func main() {
	sm := NewSafeMap()
	sm.Set("counter", 0)

	var wg sync.WaitGroup

	// Many frequent readers.
	for i := 0; i < 10; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			for j := 0; j < 5; j++ {
				v, _ := sm.Get("counter")
				fmt.Printf("reader %d saw %d\n", id, v)
				time.Sleep(10 * time.Millisecond)
			}
		}(i)
	}

	// One occasional writer.
	wg.Add(1)
	go func() {
		defer wg.Done()
		for i := 1; i <= 3; i++ {
			time.Sleep(20 * time.Millisecond)
			sm.Set("counter", i)
		}
	}()

	wg.Wait()
}
```

Key points:
- The mutex sits next to the data it protects, and the map is only accessed through methods that lock.
- `defer` guarantees the unlock even on panic or early return.
- `Get` uses `RLock`, and `Set` uses `Lock`.
- Copy `SafeMap` by pointer only. Copying a struct that contains a mutex breaks it (`go vet` flags this).
- Run with `go run -race` to confirm there are no data races.
