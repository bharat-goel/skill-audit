**Open questions, and what I'd check**

1. **Log record construction (log v0.20.0 to v0.21.0).**
   - Check the v0.21.0 changelog and API docs for changes to `log.Record`, `SetBody`, `AddAttributes` and `Logger.Emit`.

2. **`WithEndpointURL` path handling.**
   - Check the `otlptracehttp` changelog for how `WithEndpointURL` treats a URL with no path.
   - In the versions I know, `WithEndpointURL` uses the URL path as given. I'm not sure it appends `/v1/traces` when the path is empty. If it doesn't, the current config would post to `/` instead of `/v1/traces`.
   - The safe change is to make the path explicit, and it works whichever way v1.45.0 behaves:
     ```go
     otlptracehttp.WithEndpointURL("http://otel-gateway:4318/v1/traces")
     ```
     Alternatively, use `WithEndpoint("otel-gateway:4318")`, `WithInsecure()` and `WithURLPath("/v1/traces")`.
   - Whether this is a v1.44.0 to v1.45.0 difference or a long-standing behavior is exactly what the release notes should settle.

3. **`Retry-After` parsing.**
   - The OTLP spec allows both delay-seconds and HTTP-date forms.
   - I can't say whether the v1.44.0 exporter honored only seconds or both, or whether v1.45.0 changed that. Check the `otlptracehttp` retry code and changelog for both releases.
   - Until then, don't rely on HTTP-date throttling hints being honored. Configure the Collector to send `Retry-After: <seconds>`, which is the form the exporter is more likely to parse.
