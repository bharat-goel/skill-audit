## Difference

**`sync.Mutex`** gives exclusive access: only one goroutine can hold the lock at a time, whether it is reading or writing.

**`sync.RWMutex`** has two modes:
- **Write lock** (`Lock`/`Unlock`): exclusive, as with a `Mutex`.
- **Read lock** (`RLock`/`RUnlock`): shared. Any number of goroutines can hold it at once, but no writer can hold it at the same time.

A writer waits for current readers to finish. Once a writer is waiting, new `RLock` calls block. This prevents writer starvation.

## When to choose which

- **Use `RWMutex`** when reads greatly outnumber writes and the critical section is long enough that concurrent readers actually save time. A read-heavy cache or config map is a typical case.
- **Use `Mutex`** by default. `RWMutex` has more bookkeeping, so it is slower per operation. If the critical section is tiny, or writes are frequent, or contention is low, it often loses to a plain `Mutex`. Measure before switching.

Two pitfalls with `RWMutex`:
- Never write while holding only `RLock`. Mutating under a read lock is a data race.
- You can't upgrade `RLock` to `Lock`. Release the read lock first. Calling `RLock` recursively can also deadlock if a writer is waiting in between.

## Example

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type Counter struct {
	mu sync.RWMutex
	m  map[string]int
}

func NewCounter() *Counter {
	return &Counter{m: make(map[string]int)}
}

// Get takes a shared read lock, so many readers can run concurrently.
func (c *Counter) Get(key string) (int, bool) {
	c.mu.RLock()
	defer c.mu.RUnlock()
	v, ok := c.m[key]
	return v, ok
}

// Set takes the exclusive write lock.
func (c *Counter) Set(key string, val int) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.m[key] = val
}

func main() {
	c := NewCounter()
	c.Set("hits", 0)

	var wg sync.WaitGroup

	// Many frequent readers.
	for i := 0; i < 10; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			for j := 0; j < 5; j++ {
				v, _ := c.Get("hits")
				fmt.Printf("reader %d saw %d\n", id, v)
				time.Sleep(10 * time.Millisecond)
			}
		}(i)
	}

	// One occasional writer.
	wg.Add(1)
	go func() {
		defer wg.Done()
		for n := 1; n <= 3; n++ {
			time.Sleep(20 * time.Millisecond)
			c.Set("hits", n)
		}
	}()

	wg.Wait()
}
```

Points to note:
- The map is never touched outside the lock, and it's unexported so callers must go through the methods.
- `defer` guarantees the unlock even on panic.
- Run it with `go run -race .` to confirm there are no data races. Removing the locks will make the race detector report them.

If you only need a read-mostly cache with stable keys, `sync.Map` is another option, but a typed map with an `RWMutex` is usually clearer and type-safe.
