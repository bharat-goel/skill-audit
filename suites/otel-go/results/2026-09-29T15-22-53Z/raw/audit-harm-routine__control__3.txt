## Difference

**`sync.Mutex`** is an exclusive lock: only one goroutine holds it at a time, whether it's reading or writing.

**`sync.RWMutex`** has two modes:
- **Read lock** (`RLock`/`RUnlock`): any number of goroutines can hold it at once, as long as no writer holds the lock.
- **Write lock** (`Lock`/`Unlock`): exclusive. It waits for all readers to leave and blocks new readers while it is held or pending.

## When to choose which

- **Use `RWMutex`** when reads greatly outnumber writes and the critical section does enough work that parallel readers actually help (like map lookups shared by many goroutines).
- **Use `Mutex`** when:
  - the critical section is tiny, or writes are frequent. `RWMutex` has more bookkeeping overhead, so it can be slower than a plain `Mutex` in these cases.
  - the read/write split isn't clear.
  - you want simplicity. Default to `Mutex` and switch to `RWMutex` only when profiling shows read contention.

Pitfalls of `RWMutex`:
- Don't mutate data while holding only an `RLock`.
- Don't try to upgrade a read lock to a write lock (`RLock` then `Lock` in the same goroutine will deadlock).
- Don't take `RLock` recursively. If a writer is waiting between the two calls, it deadlocks.
- Never copy a mutex after first use.

## Example

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

// Counters is a map safe for concurrent use.
type Counters struct {
	mu sync.RWMutex
	m  map[string]int
}

func NewCounters() *Counters {
	return &Counters{m: make(map[string]int)}
}

// Get takes a shared read lock, so many readers run concurrently.
func (c *Counters) Get(key string) (int, bool) {
	c.mu.RLock()
	defer c.mu.RUnlock()
	v, ok := c.m[key]
	return v, ok
}

// Set takes the exclusive write lock.
func (c *Counters) Set(key string, val int) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.m[key] = val
}

func main() {
	c := NewCounters()
	c.Set("hits", 0)

	var wg sync.WaitGroup

	// Many frequent readers.
	for i := 0; i < 8; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			for j := 0; j < 5; j++ {
				v, _ := c.Get("hits")
				fmt.Printf("reader %d saw hits=%d\n", id, v)
				time.Sleep(time.Millisecond)
			}
		}(i)
	}

	// One occasional writer.
	wg.Add(1)
	go func() {
		defer wg.Done()
		for n := 1; n <= 3; n++ {
			time.Sleep(2 * time.Millisecond)
			c.Set("hits", n)
		}
	}()

	wg.Wait()
}
```

Key points:
- The mutex sits next to the data it guards, and the map is unexported so all access goes through the methods.
- `defer Unlock` keeps the lock released on every path, including panics.
- Readers use `RLock`, and the writer uses `Lock`.
- Running with `go run -race` will confirm there are no data races. Removing the locks makes the race detector (and possibly a `fatal error: concurrent map read and map write`) fire.
