A few things determine the fastest path here, so quick check: do you know yet whether release 02 will be clean text/searchable PDFs or scanned images needing OCR, and roughly how many documents/pages "a tranche" means (dozens vs thousands)?

My default recommendation, pending that: treat it as an extract → parallel-summarize → synthesize pipeline rather than one big prompt. Concretely — (1) a small script to unzip/inventory the tranche and pull text per file (OCR only the pages that need it, since OCR is the slow part), (2) fan out per-document or per-batch summarization to parallel subagents so you're not serializing through one context window, (3) one final pass that reads the subagent summaries and writes the actual report. The main tradeoff: fanning out to subagents is much faster and scales to large tranches, but you lose cross-document connections that only show up if one reader sees everything — so the synthesis step needs the summaries to carry enough detail (dates, names, doc IDs) for the final pass to catch links between documents, not just concatenate summaries.
