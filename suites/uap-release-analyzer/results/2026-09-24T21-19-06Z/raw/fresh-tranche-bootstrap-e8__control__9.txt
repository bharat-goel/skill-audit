For a document tranche like that, the fastest reliable path is a two-stage pipeline rather than reading everything serially yourself:

1. **Ingest + extract**: a small script that unzips/downloads the files, converts each to text (OCR if any are scanned PDFs), and tags them with metadata (filename, date, doc type) — this part should just be code, not agent time.
2. **Parallel summarize, then synthesize**: fan out per-document summarization to subagents (or batched Claude calls) since docs are independent, but always follow with one final synthesis pass that reads all the summaries together and writes the actual report — skipping that last pass is the main failure mode, since parallel summaries alone read as disjointed and miss cross-document connections (e.g., the same event described in two different files).

The main tradeoff is speed vs. coherence: more parallelism in step 2 is faster but pushes more weight onto that final synthesis step to hold the narrative together.
