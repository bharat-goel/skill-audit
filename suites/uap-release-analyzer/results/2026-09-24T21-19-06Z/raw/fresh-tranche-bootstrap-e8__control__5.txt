Fastest realistic path: don't wait for the drop to improvise — build the pipeline now against release 01's files, so on day one of release 02 you just point it at the new folder. The shape is usually (1) bulk-download + normalize (OCR any scanned PDFs, dedupe, convert everything to text with metadata intact), (2) per-document structured extraction via LLM into a consistent schema (who/what/date/claim/source), (3) a synthesis pass that clusters extractions into themes and diffs against what release 01 already established, (4) a templated report generation step, then a human read-through before anything goes out. The main tradeoff is extraction fidelity vs. speed — cheap/fast per-doc summarization is fine for triage, but the actual report should re-verify quoted claims against the source text rather than trusting the LLM's first-pass extraction.
