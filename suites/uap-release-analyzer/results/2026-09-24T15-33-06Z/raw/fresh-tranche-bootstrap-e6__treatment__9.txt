The fastest path once release 02 lands in a sibling folder next to release 01:

```
scripts/run_all.py <release_root>
```

That chains all four pipeline steps — inventory → text extraction → analytics → REPORT.md — in order, and each step is idempotent/incremental, so you can re-run it safely if it stalls partway (e.g. on a chunked extraction).

A few things worth knowing before you kick it off:

1. **Check the agency vocab first.** If release 02 introduces new filename prefixes, `OTHER` will balloon in the inventory. Worth a quick glance at `inventory.csv` after step 1 — if `OTHER` is above ~3%, add the new prefixes to `references/agency_vocab.md` and `PREFIX_RULES` in `inventory.py`/`analyze.py` before moving on, otherwise the report undercounts by agency.
2. **No OCR by default.** Scanned FBI/NARA files will show up as 0-char text extractions — expected, not a bug. The report's "What's missing" section flags them; OCR is a separate follow-up if you want it.
3. **Cross-tranche comparison is free upside.** Since you'll have `release_01/` and `release_02/` as siblings, once both reports exist it's a natural follow-up to ask "what's new in 02 vs 01" — worth doing after the base report if you want that angle.
